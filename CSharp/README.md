# SEFM - standalone C# version

Download the ready-to-run executable and complete data package from https://github.com/karagang/SEF-Statistical-Events-Forecasting-Model/releases/tag/v1.0.0. The executable is a release asset and is not stored in Git.

This is an independent Windows x64 application. It has its own copy of all 55 regional input folders and generates its own forecasts, charts, PDF reports, PowerPoint reports and CSV summaries. It does not call Python, Node.js, Codex, Excel or PowerPoint. Its .NET runtime is included in `SEFM.exe`.

The neighbouring `Python` folder is a separate implementation. Changes to an observation CSV in one version do not change the other version's data.

## Start the application

Double-click **SEFM.exe** to open its menu. Choose to forecast all regions, build reports, do both, or run the verification tests. You can also double-click **RunForecasts.cmd** or **RunAll.cmd**.

For PowerShell, open a terminal in this CSharp folder:

```powershell
.\SEFM.exe forecast
.\SEFM.exe reports --year 2026
```

The first command recalculates all regional results. The second collects those results into the combined reports. **The easiest option is:**

```powershell
.\SEFM.exe all
```

This runs all regions and automatically derives the report year from their inputs. All selected regions must have the same latest observation year for a combined report.

## Annual procedure: forecasting 2027

1. Edit **this CSharp folder's** `[region folder]\input\observations.csv` for every region.
2. Keep the `Year,DOY` header and all existing observations. Add each region's actual 2026 observation as the final row. For example, `2026,204.0` means that region's event occurred on day 204 of 2026. Use the real DOY for each region.
3. Save each file as CSV. Years must be consecutive, ascending and unique, with one observation per year. January 1 is DOY 1. Leap years permit DOY 366.
4. Double-click `RunAll.cmd`, or run `.\SEFM.exe all` from PowerShell in this folder.
5. Confirm the console reports **55/55 regions completed**. If a region fails, correct the problem shown in its `FAILED` message and `forecast_run_errors.json`, then rerun. Review the dates, plots and warnings before use.
6. Each region receives an **output-2027** folder. The combined PDF, PowerPoint and summary CSV appear in **reports\output-2027**. Existing output-2026 folders remain available.

The forecast year is calculated as the final observed year plus one. Enter the observed year, 2026, in the CSV. There is no separate forecast-year input to change for model calculation, and the means are recalculated automatically.

If you prefer separate commands:

```powershell
.\SEFM.exe forecast
.\SEFM.exe reports --year 2027
```

For 2028, append the actual 2027 observations and follow the same steps.

## Files produced

Each regional `output-YYYY` folder contains:

* `forecast.txt` and `forecast.json`: both forecasts, dates, settings, provenance hash and method warnings.
* `series.csv`: Year, DOY, Mean and RollingMean. Unavailable first-year means remain blank.
* `forecasts.csv`: forecast year, raw fractional DOY, rounded DOY and calendar date for both methods.
* Five plots, each in PNG and PDF: history with forecasts, observations and means, power spectrum, periodogram, and model forecasts.

The combined `reports\output-YYYY` folder contains `SEFM-YYYY.pdf`, `SEFM-YYYY.pptx` and `forecast_summary.csv`. The supplied 2026 products were generated by this C# application from the copied observations ending in 2025. No example 2026 observation has been added to the operational input files.

Reports reject missing outputs, stale inputs, inconsistent forecast years, and mixed smoothing/timing settings. Rerunning the same year replaces that year's generated files. Back up a year's output folder first if you need to preserve a particular run.

PowerPoint history and model charts are editable and contain embedded Excel workbooks with independent numeric year coordinates. Spectral diagnostic figures are embedded PNGs. Chart/workbook data use six decimal places for Office compatibility; JSON and CSV calculations retain full double precision. The PDF contains a cover, summary pages and three pages per region. PowerPoint contains a cover and three slides per region.

## Select regions and calculation modes

```powershell
.\SEFM.exe all --region "1-Peel Sound Area"
.\SEFM.exe reports --year 2027 --region "1-Peel Sound Area"
```

Repeat `--region` to select several exact folder names. `--root PATH` selects another complete project/data folder, and reports accept `--destination PATH`.

The defaults match the latest Python program: **FFT-selected smoothing with expanding early averages**, and **next-year forecast timing**.

```powershell
.\SEFM.exe forecast --smoothing workbook
.\SEFM.exe forecast --smoothing legacy --timing legacy
```

* `fft`: FFT the observations, select the positive-frequency bin with the largest power, invert its frequency, and round half up to a whole-year window. Smooth the two-year means using that window, expanding until the window fills. A constant series has no dominant period and uses a one-year window.
* `workbook`: use the contiguous window previously extracted from the workbook's formulas. It uses consistent expanding early averages; it need not reproduce workbook-specific omitted early rows. An ambiguous workbook window causes an explicit failure.
* `legacy`: use the retained `input\legacy_rolling_mean.csv` snapshot. This mode requires the unchanged original migrated observations and is for historical comparisons.
* `--timing next-year`: evaluate the quadratic at `L+1` and select the first OFBM recursive prediction.
* `--timing legacy`: evaluate the quadratic at `L` and select recursive prediction `xp[L]`, reproducing the old programs' timing.

Legacy commands replace that year's generated results. Run the default forecast command again to restore default results before building the regular report.

## Method notes

The two-year mean at year t is `(DOY[t-1] + DOY[t]) / 2`. This reproduces the supplied workbooks. The paper describes an FFT-selected moving average but does not explicitly prescribe this two-year preprocessing step. The default smooths those two-year means for continuity with the Python version and the workbooks.

The historical **FFT forecast** is a quadratic polynomial forecast after FFT-selected smoothing. It is not a Fourier extrapolation. OFBM retains the supplied Python filter's initialization and unusual nested coefficient updates. Agreement between C# and Python demonstrates numerical reproducibility, not forecast skill or scientific validation of the translated filter.

Dates use one half-up rounding rule for both integer DOY and calendar date. Out-of-year predictions are flagged and have no calendar date. The Lake Melville VCPI workbook/text discrepancy and long-period smoothing warnings are retained in the regional metadata and output notes.

## Verification

```powershell
.\SEFM.exe self-test
```

The test suite compares 274 supported combinations of Python smoothing/timing outputs across all 55 regions, and the full original legacy recursive prediction vectors. It also checks a known FFT period, constant data, expanding means, leap years, rounding, invalid/duplicate/gapped years, and the 2026-observation-to-2027-forecast transition.

The immutable comparison inputs are in `reference\baseline_inputs`; they are test fixtures. They are separate from the operational region folders, so annual updates do not invalidate numerical regression tests. Baseline JSON includes the source Python code hash. Test tolerance is 0.0000001 day. The tested maximum forecast/fit difference was less than 0.000000000001 day. See `reference\verification.txt` for the completed checks.

The 2026 PowerPoint passed package, layout, embedded-workbook/chart-data checks and first-party import. This environment's presentation image renderer does not provide a reliable native visual preview, so open the deck in PowerPoint for a final visual review. The app itself does not use that renderer or require PowerPoint to generate reports.

## Optional import from original workbooks

The supplied inputs are already migrated; no import is needed for annual updates.

```powershell
.\SEFM.exe import --source "D:\path\to\original\regional\folders"
```

This reads the active worksheet's columns A (Year) and C (Obs), preserves the column-E contiguous window when unambiguous, and retains the original `yz.txt` as a compatibility snapshot when present. It reads XLSX ZIP/XML directly, without Excel. Existing regional input folders are skipped, protecting annual updates. `migration_audit.json` records new imports. The importer was checked against all 55 supplied original workbooks.

## C# source and rebuilding

`src\SEFM.csproj` and its C# files contain all application code. Open the project in an IDE supporting .NET 10, or install Microsoft's [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) and run:

```powershell
.\build.ps1
```

Rebuilding requires the SDK and access to Microsoft's runtime packages on the first restore. Running the supplied executable requires neither a separate .NET installation nor internet access. It targets Windows x64, uses Windows GDI+ for plots, and includes the .NET Windows Desktop runtime in the executable. Microsoft runtime license/notices are in `runtime-notices`.

Implementation: arbitrary-length mixed-radix FFT with prime-factor direct transforms, scaled quadratic QR least squares, exact port of the legacy filter updates, System.Drawing charts, a small PDF writer, and native Open XML PowerPoint/workbook generation. No third-party C# packages or Python/Node subprocesses are used.
