C#: download, extract, run

  1. Download the standalone Windows x64 package.
  2. Extract the complete archive. Keep SEFM.exe, the regional folders and the documentation together inside CSharp.
  3. Double-click SEFM.exe for the menu, or RunAll.cmd to run all forecasts and build the combined reports.

The .NET runtime is bundled. Running the supplied executable requires no Python, Node.js, Codex, Excel, PowerPoint or separate .NET installation. Rebuilding from source requires the .NET 10 SDK.

.\SEFM.exe all

The supplied input records end in 2025, so an unchanged first run forecasts 2026. Use the annual update below to forecast 2027 from actual 2026 observations.

Python: create an environment

Download and extract the Python package. Python 3.12 is recommended. From the extracted Python folder, create a local environment and install the requirements:

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_forecasts.py
.\.venv\Scripts\python.exe build_reports.py --year 2026 --pdf-only

These Windows PowerShell commands generate the forecasts and the combined PDF. On other systems use that environment's Python executable. The original JavaScript PowerPoint helper uses a Codex-specific library; a fully standalone alternative is described below.

The 2027 procedure, step by step

  1. Work in your chosen version's folder. Open each selected region's input/observations.csv.
  2. Append the real 2026 observation. Keep the Year,DOY header and all existing rows. Add one row such as 2026,204.0, using that region's actual event DOY. The number 204.0 is an example, not supplied forecast data.
  3. Check and save the CSV. Years must be unique, ascending and consecutive. January 1 is DOY 1. Each region has one observation per year. Update all 55 regions before building the full annual report.
  4. Run the model. The last observed year plus one determines the forecast year automatically.
  5. Check the run. Expect 55/55 regions completed. Read any failure messages and forecast_run_errors.json. Inspect the dates, plots and method warnings before using them.
  6. Open the results. Each region receives output-2027. Combined reports are under reports/output-2027.

C# commands

.\SEFM.exe all

Python commands

.\.venv\Scripts\python.exe run_forecasts.py
.\.venv\Scripts\python.exe build_reports.py --year 2027 --pdf-only

Enter the observation year, 2026, in the CSV. Do not add an empty 2027 observation or edit a separate year file. The program calculates the means, rolling window and forecast year. Running the same forecast year again replaces that year's generated files; preserve a copy first if you need a particular run.

For the 2028 forecast, append actual 2027 observations and repeat the procedure.

PowerPoint from Python results

The standalone C# report writer understands the JSON and plot files produced by Python. To generate a PDF, editable PowerPoint and CSV summary from Python's already calculated results, download the C# package and keep the two extracted folders side by side:

SEFM-project/
  Python/
  CSharp/

After running the Python forecasts, run the following from their common parent folder:

.\CSharp\SEFM.exe reports --root .\Python --year 2027 --destination .\Python\reports

This collects the saved Python results; it does not replace them with C# calculations. Alternatively, use the C# version for the complete calculation-and-report workflow. The retained report_deck.mjs helper remains available to users with its configured Codex presentation runtime.

Choose a single region

.\SEFM.exe all --region "1-Peel Sound Area"
.\.venv\Scripts\python.exe run_forecasts.py --region "1-Peel Sound Area"

Use the exact region folder name and repeat --region to select several. Report generation checks the selected regions for consistent years, current input hashes, completed outputs and matching smoothing/timing settings.

When a run does not complete

  • Unknown region: use the exact folder name, including its spaces and prefix.
  • Duplicate or missing years: correct the input rows; missing observations are not interpolated silently.
  • Stale forecast: rerun forecasts after editing a CSV, then build reports again.
  • Wrong report year: the input must end in the year before the requested forecast year.
  • Mixed settings: rerun all selected regions with the same smoothing and timing choices.
  • No workbook window: the historical workbook had no unambiguous contiguous window. Use the default FFT smoothing.
  • Legacy snapshot rejected: compatibility smoothing requires the unchanged migrated observation record. Use the default mode for annual updates.

Check the implementation

.\SEFM.exe self-test

The C# tests use immutable reference inputs, so operational annual updates do not invalidate their numerical comparisons. Agreement with the earlier programs is a reproducibility check, not a measurement of forecast accuracy. Read the method notes before interpreting results.
